Method & Evaluation Report

把完整病史，变成可验证的回答路径。

CareHarness 不是把所有历史直接塞给模型，而是将患者记忆组织为版本化 Patient Graph，再按题型和时间算子进行确定性 Action 路由，构造小而完整的 Working Subgraph，最后交给 Qwen 生成答案。

01 · Method

整体方法

核心思路是把“模型自己在长上下文中找事实、辨时间、拼因果”拆成可追踪的记忆构建与查询时控制步骤，降低便宜模型的检索和推理负担。

01历史 Session保留患者、医生、时间与就诊边界
02原子 Evidence拆分事实，绑定来源与时间
03六类 State组织症状、状态、计划与纵向变化
04Patient Graph记录更新、替代、冲突和时序
05Action 路由按题型、时间算子与预算选择步骤
06Working Subgraph只保留当前问题需要的证据链
07Qwen 回答在校验后的紧凑上下文中表达答案
BC

Background & Context

诊断、生活背景、疾病类型和长期上下文。

PE

Patient Experience

症状、感受、主观体验及其发生模式。

PA

Patient Adaptation

患者行为、接受度、执行困难与应对方式。

CS

Clinical State

检查、血糖、C 肽及当前临床状态。

CP

Care Plan

治疗计划、个体约束及查询时推理结论。

LO

Longitudinal Outcome

前后变化、疗效、复发和长期趋势。

02 · Action Policy

Action 如何选择

当前是 configured task-class policy：规则确定、可复现，但不是 learned policy，也不是每题自由组合任意 Action。

准确表述：按题型和 temporal operator 进行确定性条件路由；每题真正变化的是选中的 State、Session、Evidence 和 query-time CP State。

04 · Why It Works

为什么提高

主要收益来自结构化控制，而不是堆更贵的模型：让 Harness 先完成检索、消歧、版本解析和因果组织，Qwen 只需在小而可靠的上下文中表达答案。

01 / RETRIEVAL

Session 锚定 + 原子 Evidence

同时使用 State 候选、Session anchor 和直接 Evidence fallback，避免相似的后续复述挤掉原始事实。

02 / TIME

显式版本与时间消歧

通过 discriminate 与 reconcile 区分首次事件、当前状态、历史状态及已被替代的版本。

03 / EXACTNESS

精确答案规范化

对 SAID、VPT 18–22 V、12–13 mmol/L 等生成证据绑定的规范化 State，减少自由改写。

04 / OPTIONS

逐选项证据平衡

MQ 为每个选项分别保留支持与反证，再统一输出选项集合，降低只命中最显眼选项导致的漏选。

05 / CONSTRAINT

患者专属 CP State

把成本、执行困难、病程和风险转成可追踪的决策约束，避免退化为通用医疗建议。

06 / CAUSALITY

MCD 保留完整中间节点

强制输出患者证据与每一跳机制，不允许从诱因直接跳到结论。

深夜高 GI → HPA 激活 → 皮质醇 → 肝糖输出 → 黎明现象 → 晨糖升高
07 / VERIFY

修复 State 生命周期

query-time CP State 不再在 current 视图中被误判为 superseded，正确推理可以到达最终答案。

08 / COMPRESSION

正确链路优先的上下文压缩

专用 CP State、直接支持 State 与 Evidence 优先，减少重复 Session 和图元数据抢占注意力。

09 / MODEL

便宜模型也能工作

正式 Answer 与 Judge 均使用 qwen3.5-flash；提升主要由 Harness 结构提供，而非昂贵模型替换。

05 · Validation Boundary

如何解释这组结果

把正式成绩、当前代码和泛化结论分开，才能正确理解方法有效到了什么程度。
